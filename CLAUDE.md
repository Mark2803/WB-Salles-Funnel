# WB Воронка — инструкция для работы с кодом

Инструмент магазина «Чайный Мастер» на Wildberries: сбор данных по WB API, сводка, юнит-экономика, стратегии и симулятор. Владелец — Марк. Общение и комментарии в коде — на русском, объяснять простыми словами: Марк не программист.

## Главное

- **Без сторонних библиотек.** Node.js ≥ 22.5: `node:http`, `node:sqlite`, `fetch`, `node:test`. Не добавлять npm-зависимости без явной просьбы — на сервере их некому обновлять.
- **Только чтение из WB.** Инструмент ничего не меняет в кабинете WB (цены, ставки, ответы на отзывы). Токен — персональный, «Только чтение».
- **Секреты только в `.env`** (в git не коммитить): `WB_API_TOKEN`, `DATABASE_URL`, `SESSION_SECRET`. Токен не выводить в логи и на экран.
- **Вход — только через «Менеджмент»** админки Чайного Маркета (PIN), своего пароля нет. Админка открывает `…/management/wb-funnel/#t=ТОКЕН`; страница меняет токен на сессию (`POST /api/login`), `src/management-auth.mjs` проверяет sha256 токена по `management_access_tokens` базы сайта утилитой `psql` (пароль базы — через переменные окружения, не в аргументах). Сессия живёт до конца токена (60 мин). Карточка — `MANAGEMENT_TOOLS` в TeaMarketV2 (`рефакторинг`).
- **Методы WB API** взяты из официальной спецификации dev.wildberries.ru (снимок 09.11.2026). WB часто меняет методы — при ошибке 404/400 сначала сверить с актуальной документацией. Лимиты: аналитика и реклама — 3 запроса/мин, финотчёт — 1/мин (см. `src/wb/client.mjs`).
- **Органических показов в API нет**: воронка начинается с переходов в карточку. Показы/CTR — только по рекламе. Поиск и позиции — только с подпиской «Джем».
- **Эффекты стратегий — допущения**, они помечены `kind: 'assumption'` и видны пользователю. Не выдавать прогноз за факт.

## Себестоимость

Не вводится в этом инструменте: при каждом сборе читается Google Таблица «Финансы V3», лист «Себестоимость» (колонки «Артикул», «Наименование», «Себестоимость») роботом Google Менеджмента, только чтение (`src/costs.mjs`, `src/google-sheets.mjs`). Связь — по артикулу продавца WB (`vendorCode`, например `SMOLA-SMILE-10,5`), без учёта регистра. Товары из таблицы помечаются `cost_source = 'sheet'` и вручную не меняются (API отвечает 409); вручную — только артикулы, которых нет в таблице. Править себестоимость — в Менеджменте (`/management/costs/`, репозиторий Managment).

## Какие товары отслеживаются

Список задаётся галочкой «Воронка WB» в Менеджменте (`/management/costs/` → «Товары и остатки»): Менеджмент пишет артикул WB (nmID) в колонку «Воронка WB» листа «Себестоимость». При каждом сборе воронка читает эту колонку (`parseTrackedNmIds` в `src/costs.mjs`, `resolveTrackedNmIds` в `src/sync.mjs`) и запоминает список в таблице `meta`. Пока колонки нет — `TRACKED_NM_IDS` из `.env`; если таблица недоступна — последний известный список. Убранные товары скрываются, их данные не удаляются.

## Реклама (вкладка «Реклама», `src/ads.mjs`)

- Кампании берутся все: статусы 4 (готова), 9 (активна), 11 (пауза) и завершённые за 30 дней. Ставки WB — в копейках, храним в рублях (`campaigns.bids_json`). Товары с действующей рекламой отслеживаются автоматически (`campaignNmIds` в `sync.mjs`), шаг «Реклама» идёт первым.
- Формулы (комментарий в начале `ads.mjs`): прибыль с заказа = прибыль с продажи × выкуп; ДРР = цена клика / (конверсия × цена); безубыточная ставка = прибыль с заказа × конверсия; ставка под цель = цель ДРР × цена × конверсия.
- Аукцион второй цены: WB списывает меньше ставки — доля списания (`chargeRatio`) берётся из факта кампании (≥10 кликов), ставки в советах пересчитываются через неё.
- Конверсия: факт рекламы (≥100 кликов) → карточка за 30 дней (≥100 переходов) → допущение 3%. Объём при другой ставке — допущение (клики ∝ ставка^0,7, не больше дневного бюджета).
- ДРР в расчётах — от цены продавца (как прогноз); «как в кабинете WB» — от суммы заказов в ценах покупателя (`drrWbPct`), обычно ниже.
- Прогноз снимается автоматически (`ad_forecasts`) при первом появлении кампании и при смене ставки или дневного лимита (>20%), с записью в журнал; сравнение «прогноз → факт» — в среднем за день с даты снимка.
- Комиссия в юнит-экономике: финотчёт → тариф WB по предмету (FBW, `subject_tariffs`) → настройки; источник показывается.
- Только чтение: ставки и бюджеты инструмент не меняет, только советует.

## Команды

- `npm start` — запуск; `npm run dev` — тестовые данные (`WB_MOCK=1`).
- `npm test` — автотесты (сеть не нужна). Запускать перед каждым коммитом.
- `npm run collect` / `npm run collect -- full` — разовый сбор.
- `npm run check` — проверка токена (категории, срок, только чтение).
